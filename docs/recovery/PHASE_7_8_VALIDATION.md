# Phase 7 and 8 Validation Handoff

This checklist is for the Linux validation/signing machine. It assumes Java, MongoDB, the Android SDK, device access, and staging or production secrets are available there.

**Status (2026-08-22):** Server-side sections are verified on the Ubuntu 22.04 staging VM — `sbt test`/`compile`, the three HTTP probes (version JSON with configured origin, public spaces array, protected endpoint rejection), tile/archive links using `$PUBLIC_BASE_URL/api/floortiles/...` with `/` separators, and the runtime URL audit (active trees clean; see RECOVERY_AUDIT.md for classification). Remaining: Android build validation and device workflow tests on this machine, plus production-origin substitution when university IT supplies DNS/TLS.

## Required Local Configuration

Create `server/conf/app.private.conf` from `server/conf/app.private.example.conf` and set:

```hocon
public.baseUrl="https://<owned-staging-or-production-origin>"
server.address=${public.baseUrl}
server.port="443"
mongodb.hostname="localhost"
mongodb.port=27017
mongodb.database="anyplace"
mongodb.app.username="<app user>"
mongodb.app.password="<app password>"
password.salt="<controlled salt>"
password.pepper="<controlled pepper>"
cors.allowedOrigins=["https://<owned-staging-or-production-origin>"]
```

Do not use the illustrative E-JUST hostname until university IT has assigned DNS and TLS material.

Create `clients/android-new/local.properties` on the validation/signing machine:

```properties
PUBLIC_BASE_URL=https://<owned-staging-or-production-origin>
MAPS_API_KEY=<restricted Android Maps key>
ANDROID_KEYSTORE_FILE=/absolute/path/to/ejust-release.jks
ANDROID_KEYSTORE_PASSWORD=<secret>
ANDROID_KEY_ALIAS=<alias>
ANDROID_KEY_PASSWORD=<secret>
ANYPLACE_BOOTSTRAP_USERNAME=<optional test account>
ANYPLACE_BOOTSTRAP_PASSWORD=<optional test password>
ANYPLACE_BOOTSTRAP_ACCESS_TOKEN=<optional test token>
```

The checked-in `clients/android-new/secure.properties` is only a template. Real keys and passwords must remain local to the validation/signing machine or the university signing custody process.

## Server Validation

From `server/`:

```bash
./sbt test
./sbt compile
./sbt run
```

With the server running:

```bash
curl -fsS "$PUBLIC_BASE_URL/api/version"
curl -fsS -X POST "$PUBLIC_BASE_URL/api/mapping/space/public" -H 'Content-Type: application/json' -d '{}'
curl -i -X POST "$PUBLIC_BASE_URL/api/auth/mapping/space/access" -H 'Content-Type: application/json' -d '{}'
```

Expected results:

- `/api/version` returns JSON and uses the configured public origin in its address field.
- `/api/mapping/space/public` returns a JSON object with `spaces`.
- `/api/auth/mapping/space/access` is mounted and protected, returning an auth or validation error without a token.
- Floor tile/archive links generated by `/api/floortiles/:buid/:floor_number` use `$PUBLIC_BASE_URL/api/floortiles/...` with `/` separators.

## Android Build Validation

From `clients/android-new/`:

```bash
./gradlew :logger:assembleDebug :navigator:assembleDebug
./gradlew :logger:assembleRelease :navigator:assembleRelease
```

Check package identities:

```bash
aapt dump badging logger/build/outputs/apk/debug/logger-debug.apk | grep package:
aapt dump badging navigator/build/outputs/apk/debug/navigator-debug.apk | grep package:
```

Expected package IDs:

- `eg.edu.ejust.anyplace.logger`
- `eg.edu.ejust.anyplace.navigator`

Check signing separation:

```bash
apksigner verify --print-certs logger/build/outputs/apk/debug/logger-debug.apk
apksigner verify --print-certs logger/build/outputs/apk/release/logger-release.apk
apksigner verify --print-certs navigator/build/outputs/apk/debug/navigator-debug.apk
apksigner verify --print-certs navigator/build/outputs/apk/release/navigator-release.apk
```

Expected result: debug and release certificate fingerprints differ. Production artifacts require university signing custody.

## Device Workflow Validation

Install as new applications:

```bash
adb install -r logger/build/outputs/apk/debug/logger-debug.apk
adb install -r navigator/build/outputs/apk/debug/navigator-debug.apk
```

Run these launch checks against staging data:

- Local login or configured test-account bootstrap.
- Space list load.
- Floor list load.
- POI load.
- Floorplan download.
- Same-floor POI routing and route display.
- Cross-floor POI routing and route display.
- Logger Wi-Fi/radiomap smoke upload with disposable data.
- Network capture confirms active Android requests target only the configured owned origin and deliberate third parties such as Google Maps.

Google Sign-In, standalone SMAS, and legacy `clients/android/` are not Phase 7 launch acceptance targets.

## Runtime URL Audit

Before release, run:

```bash
rg -n "anyplace\\.cs\\.ucy\\.ac\\.cy|ap\\.cs\\.ucy\\.ac\\.cy|map\\.beout\\.ai|/anyplace/floortiles" server/app server/conf clients/android-new clients/web docs
```

Classify remaining hits. Copyright headers, historical docs, and deprecated clients may remain only when they are not active runtime requests. Active server, active web share links, Android endpoints, generated links, proxy/TLS, and CORS must derive from the deployment-supplied public origin.
